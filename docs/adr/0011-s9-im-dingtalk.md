# ADR-0011 S9：IM 网关与钉钉接入

日期：2026-11-17　状态：已采纳（钉钉真机验证待做，见文末）

## 背景

§12.3 要求接入钉钉企业内部应用（Stream 模式），且 IM 只是入口和通知渠道（INV-06），未映射的外部用户不得映射到任何平台用户、不继承权限（INV-20），重复投递不产生重复效果（INV-16、FR-IM-07）。§12.3 也要求“IM 网关按适配器接口设计，核心逻辑用模拟适配器测试”。

## 决定

### 1. 适配器接口 + 与供应商无关的网关

- `modules/im/types.ts`：入站事件统一成 `message / edit / recall / lifecycle` 四种；适配器只负责收发：
  - `sendGroup`、`reply`、`fetchAttachment`；
  - 以及两个上限：`maxChars` 和每群每分钟条数。
- `modules/im/service.ts`：绑定、身份、命令、入站、出站镜像全部在这里，与供应商无关。
- `modules/im/mock.ts`：模拟适配器，用于 CI 和 e2e。它记录发出的消息，并能注入失败（普通错误、限流、机器人被移出、群解散、权限回收）。
- `modules/im/dingtalk.ts`：钉钉适配器，负责：
  - Stream 帧解析与应答；
  - 机器人回调解析；
  - OpenAPI 发群消息、单聊、会话 webhook 回复、附件下载；
  - 错误归类。

### 2. 入站：先落作业，再确认

- Stream 帧到达后，网关只做一件事：把事件写成 `im.inbound` 作业（去重键为供应商消息 ID），然后应答。
- 真正的处理在作业里完成，因此有重试和死信（FR-IM-08）。
- 处理失败的帧**不应答**，钉钉会重投；重投是安全的。
- 去重分三层：
  1. 在途作业：作业去重键；
  2. 已处理的普通消息：`message (source, external_id)` 唯一键；
  3. 命令和私聊：幂等记录（24 小时）。
- 同一群的入站作业带同一并发键，按顺序处理。

### 3. 身份：真实作者或“外部成员”，没有第三种

**已映射**（`external_identity`）且是项目成员：用**本人**的 Ctx 写入，走与 Web 完全相同的权限、限流和提及解析。在 `at_only` 模式下，网关在正文前加上船长提及，所以船长被唤醒的方式与 Web 中 @船长 一致。

**未映射**，或已映射但不是该项目成员：

- 每个 IM 账号对应一个 `principal.kind = 'external'`。它不对应用户，也不是任何项目成员。
- 显示名固定为“外部成员”。钉钉昵称只存进 `blocks.im.senderNick`，不用作显示名，避免冒充。
- 提及会被清空，所以这类消息不会唤醒任何 Agent，也不会给任何人发通知。
- 消息事件的 `authorKind` 为 `external`。船长消费者只响应 `human`，摘要只统计人类发言。

`chat.send` 的 `external` 选项只允许系统 Ctx（网关）使用，否则拒绝。

**绑定码**（IM-补1）：

- 用户在 Web 生成 8 位绑定码（10 分钟内有效、只能用一次；生成新码时旧码作废，库里只存哈希），然后私聊机器人发送。
- 每个 IM 账号 15 分钟内最多尝试 5 次。
- 一个 IM 账号已绑定到别人时，拒绝绑定。
- 管理员可以批量映射（`identity.map_any`）。

### 4. 命令（IM-补5）

| 命令               | 谁能用                                  | 说明                                                     |
| ------------------ | --------------------------------------- | -------------------------------------------------------- |
| `/help`、`/status` | 所有人                                  | `/status` 只给计数和 Web 链接                            |
| `/summary`         | 已映射成员                              | 以本人身份写入 `/summary`，船长消费者照常处理            |
| `/task 标题`       | 已映射且有 `task.create` 权限           | 调用与 Web 相同的 `tasks.create`，人类创建任务是合法路径 |
| `/bind 项目标识`   | 已映射且有 `im.bind` 权限（Maintainer） | 把本群绑定到项目主群                                     |

- 每个命令都有回执。
- 提议确认、决策确认、审批**不提供 IM 命令**（IM-补6），只推送 Web 链接。

### 5. 出站镜像（FR-IM-04、IM-补2、IM-补8）

- `im-outbound` 消费者监听 `message.created` 和 `approval.requested`，生成 `outbound_delivery` 记录（同一绑定、同一消息唯一），再由 `im.deliver` 作业投递。
- **镜像范围**：Agent 回复、卡片（提议、任务、摘要、追问、决策）、系统通知、审批链接。
- **不镜像**：
  - 来自 IM 的消息；
  - 线程内的消息；
  - Web 中的人类发言（`mirrorHumans` 可以打开）。
- **格式降级**：代码块转为引用行，表格转为“ · ”分隔，去掉 HTML、删除线、行内代码标记，提及还原为名字；超长内容在行边界截断，并附“在 Web 查看完整内容”链接。
- **限流**：
  - 每群每分钟超过上限时，延后发送，不消耗重试次数；
  - 供应商返回限流时同样处理；
  - 其他错误按指数退避重试 6 次，之后进入死信，可在「系统状态 → 死信」中重放。
- **免打扰**：时段内主动推送顺延到时段结束；如果群里 10 分钟内有人发言（正在对话），回复照常发送。
- **摘要频率**：同一绑定在间隔内（默认 60 分钟）只发一张摘要卡，多出的记为 `skipped`。

### 6. 生命周期（IM-补3）

以下任一情况都使绑定失效：

- 机器人被移出群、群解散、应用权限被回收（来自事件，或者发送时的错误归类）；
- 人工解绑。

绑定失效时：

- 未发出的投递标为 `stopped`，不再重试；
- 平台群里出现一条系统通知；
- Maintainer 收件箱收到升级提醒（人工解绑除外）。

之后可以在 Web 或用 `/bind` 重新绑定，沿用原绑定记录。一对一约束由两处保证：`binding(provider, external_chat_id)` 唯一，以及每个平台群在同一供应商下最多一个有效绑定（手写的部分唯一索引）。

### 7. Stream 连接只由一个实例持有

- 用 Postgres 会话级 advisory lock 作为租约，放在一条专用连接上。持有者连接一断，数据库就释放锁；其他实例每 15 秒尝试获取一次。
- Stream 会话断开后按指数退避重连。
- 发送不依赖租约，任何实例都可以发。
- 测试 `s9-dingtalk.test.ts` 用两个实例争抢：同一时刻只有一个在跑，持有者停止后另一个接手。

### 8. 接收模式（Q7）

- `at_only`（默认）：钉钉只投递 @机器人 的群消息（以及私聊），每条都视为对船长说的话。
- `passive`：应用有“接收全部群消息”权限时使用。
  - 未 @ 的消息只写入时间线，不唤醒任何 Agent，不产生模型调用；
  - 摘要沿用船长已有的批处理（按条数阈值触发），受项目预算约束；
  - 再加上出站摘要频率上限。
- 两种模式都已实现，并都有测试。

## 不做 / 偏差

- **IM 消息编辑/撤回同步（IM-补4）**：已实现并测试（只认原作者）。钉钉 Stream 是否推送编辑、撤回事件取决于应用权限；收不到时，钉钉侧的编辑不会同步。
- **出站卡片更新**：例如提议被确认后，钉钉里已发出的卡片不会改写（钉钉普通群消息不能编辑）。状态变化会作为新消息出现，例如任务卡片。
- **飞书（FR-IM-09）**：已接入。
  - 采用事件订阅回调（`/api/v1/webhooks/feishu`），校验 Verification Token，支持 Encrypt Key 的 AES-256-CBC 解密和 X-Lark-Signature 签名校验，回调先落作业再处理。
  - 发送：用 tenant_access_token 调用 OpenAPI，消息为交互卡片中的 markdown 元素；命令回执以回复形式挂在原消息下。
  - 事件：撤回、群解散、机器人被移出群、应用卸载，都映射到同一套生命周期处理。
  - 身份：优先使用 user_id（企业员工 ID），没有则用 `open:<open_id>`。
  - 测试：`s9-feishu.test.ts`。经真实接口路由完整走一遍：加密 + 签名的回调、绑定码、`/bind`、@船长后回复镜像成卡片、重投去重、外部成员、撤回、机器人被移出。
  - 真机验证需要飞书企业自建应用。
- **企业微信（FR-IM-10，P1）**：未做，适配器接口已预留。

## 验证

- `apps/server/test/s9-im.test.ts`（23 项，模拟适配器）覆盖：
  - 主场景第 1–3 步从 IM 群发起：@ → 船长回复和追问镜像回群 → 补充 → 提议镜像为 Web 链接；第 4 步在 Web 确认，任务卡片镜像回群；
  - 重投三层去重；
  - INV-20：外部成员、冒充昵称、非项目成员；
  - 命令权限、编辑/撤回、附件检查；
  - 重试→死信→重放、限流、免打扰、机器人移出 / 应用回收导致失效与重新绑定；
  - passive 模式、批量映射。
- `apps/server/test/s9-dingtalk.test.ts`（8 项）覆盖：
  - 钉钉回调与事件解析、错误归类；
  - OpenAPI 调用（令牌缓存、markdown 参数、会话 webhook 优先）；
  - 本地假 Stream 网关：ping 应答、回调按 messageId 应答、处理失败不应答、disconnect；
  - 租约争抢。
- `apps/server/test/isolation.test.ts` 新增绑定和 IM 身份的跨租户检查。
- Playwright `s9-im.spec.ts`（IM_MOCK）：绑定码 → 私聊绑定 → `/bind` → 时间线中的本人消息与“外部成员” → 免打扰设置 → 解绑。

**尚未验证**：真实钉钉企业应用。需要 `DINGTALK_CLIENT_ID / DINGTALK_CLIENT_SECRET / DINGTALK_ROBOT_CODE`，以及一个测试群。拿到后按 `docs/im.md`「真机验证清单」执行。其中第一项就是 Q7：确认应用能否收到未 @ 的群消息。
