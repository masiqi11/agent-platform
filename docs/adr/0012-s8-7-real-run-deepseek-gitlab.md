- @船长、回答追问、确认提议和分配、批准合并。

## 真实运行暴露并已修复的问题

前 6 次运行逐一暴露了下面这些问题。每条都已修复，并配有回归测试。

1. **思考模式的 `reasoning_content` 未回传**（#8）。多轮工具调用的第二轮返回 400。修复后，空字符串也会原样回传。
2. **DeepSeek 把工具调用写进正文**。在没有原生工具时，它会使用 DSML 标记，或 `<tool_call>name {json}</tool_call>` 格式。文本解析器现在两种都识别，并从展示给人的正文中去掉 DSML。
3. **确认分配提议后任务停在 backlog**。现在与确认任务提议的规则一致：守卫条件满足时自动进入就绪，并唤醒开发 Agent。
4. **追问卡片发出前，人已经回答了**。追问卡因此一直未关闭。现在，在请求消息之后、卡片之前出现的实质性回答，会直接作为这次追问的答复。
5. **思考模型输出被 `max_tokens` 截断**：
   - 回复为空，被误判为"模型已完成"；
   - 工具参数被截断，被当成 `{}` 执行；
   - 修复：遇到这两种情况各放大预算重试一次；开发、评审、测试 Agent 的默认输出预算按模型上下文窗口设定（32k 及以上取 8192）。
6. **INV-13：事件携带了整段 reason**。测试结论为 failed 时，摘要作为迁移原因写进事件，超过事件载荷长度上限，导致 `submit_test_result` 每次都抛错。修复后，所有带 reason 的事件只携带不超过 120 字的摘录，全文保留在记录行和审计日志里。
7. **上线后才能验证的内容被写成了验收标准**，例如"观察 24 小时 p99"。测试 Agent 据此判 failed，形成开发 Agent 永远修不好的循环。修复：
   - 船长只写合并前能验证的标准；
   - 评审 / 测试 Agent 把只能在上线后验证的标准标为 `na`，并写明由谁、如何验证。
8. **驱动脚本自身的问题**：消息作者字段、模型能力标志、分配提议、等追问卡出现后再回答、任务与代码视图的字段名。都已修正，它们不属于产品缺陷。

## 环境说明（复现用）

- 本地 GitLab：`scripts/gitlab-local.sh` 启动。
- https：用自签 CA 的 TLS 代理在 443 端口转发到 GitLab:80。代理转发时必须保留原始响应字节（关闭自动解压），否则 git 智能 HTTP 会因内容编码出错而失败。
- 当前环境有出站代理，需要把 `gitlab.localtest` 加入 `NO_PROXY`。
- DeepSeek key 只经环境变量传入，不写进仓库或日志。
