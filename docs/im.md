# 接入钉钉（IM）

钉钉群只是**入口和通知渠道**。事实源始终是 Web 控制台和数据库（INV-06）。

| 在钉钉里可以做                                    | 只能在 Web 做                 |
| ------------------------------------------------- | ----------------------------- |
| @机器人 向船长描述问题                            | 确认或驳回提议                |
| 回答船长的追问                                    | 确认决策                      |
| 查看船长回复、任务卡片、摘要、审批提醒            | 审批（IM 只推送链接，IM-补6） |
| 使用 `/help` `/status` `/summary` `/task` `/bind` | 管理 Agent、仓库              |

设计说明见 ADR-0011。

## 1. 创建钉钉应用（管理员，一次性）

1. 打开钉钉开放平台，创建**企业内部应用**，并添加**机器人**能力。
2. 消息接收模式选择 **Stream 模式**。平台主动建立连接，不需要公网回调地址（FR-IM-01）。
3. 权限至少开通：
   - 机器人发送群消息；
   - 机器人发送单聊消息；
   - 下载机器人接收的文件。
4. 发布应用，然后记下 **Client ID（AppKey）**、**Client Secret（AppSecret）**、**RobotCode**。
5. 在 `deploy/.env` 中填写：

   ```bash
   DINGTALK_CLIENT_ID=…
   DINGTALK_CLIENT_SECRET=…        # 会从日志中脱敏
   DINGTALK_ROBOT_CODE=…           # 不填则使用 Client ID
   ```

6. 重启平台（`docker compose up -d app`）。

日志中出现 `im.stream.lease_acquired` 表示有一个实例已持有 Stream 连接。多实例部署时只有一个实例持有连接，持有者退出后，其他实例在 15 秒内接手。

## 2. 绑定身份（每个成员，一次性）

1. 在 Web 左下角打开用户菜单，选择「IM 身份」，点「生成绑定码」。绑定码 10 分钟内有效，只能用一次。
2. 在钉钉里**私聊机器人**，发送这 8 位绑定码。
3. 机器人回复“绑定成功”后，你在群里的消息就以你的平台身份进入平台，命令也按你的权限执行。

管理员可以批量映射：`POST /api/v1/admin/external-identities`，请求体为 `{ provider: "dingtalk", items: [{ externalUserId: staffId, userId }] }`。

**未绑定身份的人**在平台里显示为“**外部成员**”（INV-20）：

- 没有任何权限；
- 消息不会唤醒 Agent，也不会给任何人发通知；
- 只能使用 `/help` 和 `/status`。

钉钉昵称不会被当作身份使用。

## 3. 绑定群

推荐的做法：把机器人拉进钉钉群，然后由已绑定身份的项目 **Maintainer** 在群里 @机器人 发送：

```
/bind PAY
```

这会把本群绑定到项目 PAY 的主群。也可以在 Web 的项目「IM 群」页手动绑定，需要填写钉钉群的 openConversationId。

绑定是一对一的：一个钉钉群只能绑定一个平台群，一个平台群也只能绑定一个钉钉群，重复绑定会报错。

「IM 群」页可以调整以下设置：

| 设置                  | 说明                                                                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 接收模式              | `仅 @机器人`（默认）：钉钉只把 @机器人 的消息投递给平台，每条都视为对船长说的话。`接收全部消息`：需要应用具备接收群内全部消息的权限（见第 6 节）。未 @ 的消息只记入时间线，不唤醒 Agent。 |
| 免打扰时段            | 时段内，船长的主动推送（摘要、通知）顺延到时段结束。群里 10 分钟内有人发言时，回复照常发送。                                                                                              |
| 摘要最短间隔          | 默认 60 分钟。间隔内多出的摘要只留在 Web。                                                                                                                                                |
| 同步 Web 里的成员发言 | 默认关闭。默认只同步 Agent 回复、卡片和通知。                                                                                                                                             |

## 4. 群内命令

| 命令                         | 谁能用                   | 作用                                  |
| ---------------------------- | ------------------------ | ------------------------------------- |
| `/help`                      | 所有人                   | 帮助                                  |
| `/status`                    | 所有人                   | 项目进展计数与 Web 链接               |
| `/summary`                   | 已绑定身份的成员         | 请船长更新群摘要                      |
| `/task 标题`（换行后写描述） | 已绑定身份、且是项目成员 | 创建任务；验收标准和负责人在 Web 补充 |
| `/bind 项目标识`             | 已绑定身份的 Maintainer  | 绑定本群                              |

每个命令都会回执。没有权限时，回执会说明原因。

## 5. 运维

- **出站失败**：失败后自动重试 6 次（指数退避），仍失败则进入死信。在「系统状态 → 死信」中看错误、重放，或丢弃。钉钉限流时消息会延后发送，不算失败。
- **绑定失效**：机器人被移出群、群解散、应用权限被回收时，绑定会标为失效，之后：
  - 未发出的消息停止重试；
  - 平台群里出现一条通知；
  - Maintainer 收件箱收到提醒。

  恢复方法：把机器人重新拉进群，再 `/bind` 一次，或在 Web 中重新绑定。

- **入站卡住**：在「系统状态 → 链路追踪」或死信中查 `im.inbound` 作业。同一个群的入站按顺序处理，所以一条处理失败的消息会让这个群后面的消息排队，直到它进入死信（约 5 次重试）。

## 6. 真机验证清单

以下内容在拿到企业应用凭据后执行，结果记入 ADR-0011：

1. **Q7**：在测试群里**不** @机器人 发一句话，看平台日志里有没有 `im.inbound` 作业。
   - 有：可以使用 `接收全部消息` 模式；
   - 没有：只能使用 `仅 @机器人` 模式。
2. 私聊机器人发送绑定码，确认机器人回复绑定成功。
3. 群里 `/bind <项目标识>`，确认绑定成功。
4. 走主场景第 1–3 步：@机器人 描述问题 → 船长回复和追问出现在群里 → 补充细节 → 提议卡出现，并带 Web 链接。
5. 在 Web 中确认提议，任务卡片同步回群。
6. 在钉钉里重发同一条消息（或断网重连触发重投），确认平台里没有出现重复消息。
7. 把机器人移出群，确认绑定失效、Maintainer 收到提醒。

## 7. 开发与演示：模拟 IM

设置 `IM_MOCK=true` 可以启用模拟 IM（provider `mock`）。生产环境会拒绝这个配置。启用后，管理员可以：

- 用 `POST /api/v1/dev/im/receive` 扮演群成员发消息；
- 用 `GET /api/v1/dev/im/sent` 查看机器人发出的内容。

e2e 测试 `s9-im.spec.ts` 用的就是模拟 IM。
